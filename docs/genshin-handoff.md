## 2. Architecture: how data reaches the page

```
                every 3 h (GitHub Actions)
ennead.cc  ─┐
            ├─> scripts/genshin-feed.py ──> site/genshin-feed.json ──┐
yatta.moe  ─┘            │                                            ├─> genshin.js (browser)
                         └──> site/images/genshin/splash/*.webp ──────┘     renders the page
                                                                  
enka.network <── netlify/functions/genshin-api.mjs <── browser (player lookup, PLANNED)
```

Three tiers. Pick the right one for each new page:

1. **Live tier** (`genshin-feed.json`, every 3 h): things that change during a patch. Banners,
   events, challenges, codes, the farm schedule, the character roster. Keep this file small
   (it's ~47 KB; the Lobby loads it). Don't put database-sized data in it.
2. **Database tier** (planned: `site/genshin-db/*.json`, weekly): weapons, artifacts, materials,
   enemies, achievements, full character details. Written by a second script
   (`scripts/genshin-db.py`) and workflow (`genshin-db.yml`, weekly + on demand). One file per
   page so each page loads only what it needs.
3. **Static tier** (generated HTML): the 136 character pages, built by a generator script into
   real HTML files (`site/genshin-impact/characters/<slug>.html`) so Google can index them.
   Same rule as the tool cards: **edit the generator, rerun it, never hand-edit its output.**

Plus one **backend**: the player lookup's Netlify Function (section 9). Enka's API sends no CORS
header, so the browser can't call it directly.

**Why not call the APIs from the browser?** ennead and yatta are unofficial community services.
If either goes down, a page that calls them live goes blank. The feed script keeps the last good
value per source ("if one fails, the old value for it is kept"), so the site always has data.
It's also the CODM pattern (`scripts/codm-feed.mjs`).

### Feed script rules (keep these when extending it)

- Every source is a separate job in `main()`'s `jobs` dict; a failing job prints to stderr and
  keeps the old value. Calendar-dependent jobs skip when the calendar fetch fails.
- The file is only rewritten when the data changed (`data == old` check, no timestamps), so the
  workflow only commits real changes. If you add a timestamp, the workflow will commit every 3 h.
- Send the `UA` header (`ParchromeBot/1.0 (...)`) on every request.
- Splash images: downloaded once per character (skipped if the WebP exists), 1600×800 max,
  WebP q82, alpha kept. They're never deleted (reruns reuse them). ~200 KB each.
- Third-party text reaches markup in the browser: `genshin.js` puts every string through `esc()`.
  Keep doing that for anything new.
- Local run: `python scripts/genshin-feed.py` (≈50 s; needs `pip install pillow`).

### Workflow

`.github/workflows/genshin-feed.yml`: sparse checkout of `scripts`, the JSON and
`site/images/genshin`; setup-python 3.12; `pip install pillow`; run; commit only if
`git status --porcelain` shows changes; `git pull --rebase` then push. It only runs once the
repo is pushed to GitHub. Run it by hand from the Actions tab ("Run workflow").

### 3.1 ennead.cc — `https://api.ennead.cc/mihoyo/genshin/`
Unofficial, no key. CORS works (the old page called it from the browser).

| Endpoint | Returns | Used for |
|---|---|---|
| `calendar` | `{events[], banners[], challenges[]}` | banners, events, Abyss/Theater |
| `codes` | `{active[], inactive[]}` — `{code, rewards:["Primogem ×60", ...]}` (inactive had 261) | codes |

Calendar fields:
- `banners[]`: `{id, name ("Character Event Wish", "Character Event Wish 2", "Weapon Event Wish"),
  version, characters[{id, name, icon, element ("Cryo"...), rarity}], weapons[{name, icon, rarity}],
  start_time, end_time}` (unix seconds). Character ids match yatta's.

### 3.3 enka.network — player data (for the player lookup)
- `GET https://enka.network/api/uid/{uid}/` → `{playerInfo, avatarInfoList?, ttl, uid}`;
  `?info` → playerInfo only. Verified: works with a custom User-Agent; **no CORS header**.
- `playerInfo` (verified fields): `nickname, level (AR), signature, worldLevel, nameCardId,
  finishAchievementNum, towerFloorIndex, towerLevelIndex, showAvatarInfoList[{avatarId, level,
  costumeId?}]` (+ profile picture, Theater fields in newer data — check a live response).
- `avatarInfoList` (only when the player turned on "Show Character Details"): per character
  `avatarId, propMap, fightPropMap (stat ids → values), skillLevelMap, talentIdList (constellations),
  equipList (weapon + artifacts with main/sub stats), fetterInfo`.
- Their rules (check https://api.enka.network / github.com/EnkaNetwork/API-docs before building):
  send a descriptive User-Agent, **cache each UID for `ttl` seconds**, don't hammer. Status codes:
  400 bad UID, 404 no such player, 424 game maintenance, 429 rate-limited, 500/503 their side.
- Id → name/icon maps: EnkaNetwork/API-docs `store/` JSON (characters, namecards, loc). Path names
  changed over time — check the repo.

## 4. The feed today (`site/genshin-feed.json`)

```
characters[]  {id, name, rarity, icon, element, weapon, birthday [m,d] | null, release, region}
banners[]     {name, version, start, end,
               characters[{id, name, rarity, element, icon, (5★ only:) title, affiliation, weapon, splash}],
```

badges; needs the script to keep its own memory), `history[]` banner log (or its own file),

### 5.1 Tokens (`.gi-page` in genshin.css + 11layout's `--lb-*`)

### 5.3 Images (how to add one)
1. Find it on yatta (3.2) or another official source. 2. Download it, convert to WebP with Pillow
(namecards q80, photos q80-85, icons lossless), save under `site/images/genshin/<kind>/`.
3. Reference it root-absolute (`/images/genshin/...`). Hotlinking is OK only for small icons from
yatta/HoYo's CDN that the feed already returns. Official art always sits on the dark ground with a
dark gradient over it (see `.gi-nat::before`, `.gi-look::before`, `.gi-grp-art::after`).

### 5.6 Rules that bit us
- `.gi img { display:block }` beats the `hidden` attribute, so `.gi [hidden] { display:none !important }` exists. Keep it.
- No `<img>` without `src` in markup (the design hook flags it): create it in JS.
- No decorative glows (zero-offset coloured shadows). The wish glints are the one exception.
- Phone grids must be `minmax(0, 1fr)`, not `1fr`, or one-line text (code rewards) stretches the column off-screen.
- Every page needs the base reset block (top of genshin.css). Without it the page gets the
  browser's 8px margin and a broken sidebar — that happened once this session.
- A section that switches content with tabs must not change height (Adrian, twice: the hero, then
  Nations). Nations renders every nation once, keeps the tallest as `.gi-nat-body`'s min-height,
  and re-measures on resize and once the fonts load (`nations()` in genshin.js). Do the same for
  any new tabbed section.

  portraits; `[data-end]` elements count down automatically (`tick()` every second; `.is-soon`
  under 24 h); `fit(el)` for one-line titles; server helpers `serverNow()`, `nextReset()`,
  `gameDay()`.
- localStorage only for per-viewer conveniences, always in try/catch (`gi-server`; planned: timers,
  achievements, my-characters, wish history).
- Static sections (reactions, pity) render before the feed loads; feed sections render in
  `fetch('/genshin-feed.json').then(...)` and show `.gi-empty` messages on failure.

## 9. Player lookup — full spec (front end exists on the Lobby; the rest is planned)

### Now (built)
Lobby `#lookup` form: UID input (digits only, max 10) with a live server chip from the UID's
first digit (`1/2/3 China`, `5 China (B)`, `6 America`, `7 Europe`, `8 Asia`, `9 TW·HK·MO`; for
10-digit UIDs starting with 1, the second digit — confirm with Adrian). Submit validates
`^\d{9,10}$` and says it's coming soon. **Change it to navigate to `/genshin-impact/player/<UID>`**
once the page exists.

### Backend: `netlify/functions/genshin-api.mjs`
Copy the structure of `netlify/functions/coc-api.mjs` (same style, already deployed):
- `export const config = { path: '/api/genshin' }`; `GET /api/genshin?uid=800123456[&info=1]`.
- Validate: `/^\d{9,10}$/` → else 400 `{error:'badUid'}`. Never forward anything else (no open proxy).
- Fetch `https://enka.network/api/uid/<uid>/` (`?info` when `info=1`) with
  `User-Agent: ParchromeBot/1.0 (https://parchrome.netlify.app; wildparchrome@gmail.com)`.
- Map statuses: 400→`badUid`, 404→`notFound` (cache 60 s), 424→`maintenance`, 429→`busy`,
  5xx→`enka5xx`, network error→`unreachable`.
- Cache: `Netlify-CDN-Cache-Control: public, s-maxage=<ttl from the response, default 60>`,
  `Netlify-Vary: query`, `Cache-Control: public, max-age=60`. That honours Enka's ttl and means one
  UID opened 50 times costs one Enka call.
- Pass the JSON through unchanged (or trimmed); no keys needed (Enka is public).
- CORS: `ORIGINS` list like coc-api.mjs if the GitHub Pages copy needs it.
- Deploys only through the Git-connected Netlify deploy (drag-and-drop ignores functions — see
  netlify.toml). `functions = "netlify/functions"` is already set.

### Page: `/genshin-impact/player/<UID>`
- `site/_redirects`: `/genshin-impact/player/*  /genshin-impact/player/index.html  200` (same as
  `/coc/player/*`). The page reads the UID from `location.pathname`.
- Id maps: a generated `site/genshin-enka-map.json` (characters → name/element/icons incl.
  costumes; namecards; stat ids → labels), built weekly by the db script from EnkaNetwork's
  `store/` + yatta. Keep it small.
- Sections: profile header on the player's own namecard (nameCardId → namecard art), avatar,
  nickname, AR, World Level, signature, achievements, Spiral Abyss floor-chamber
  (towerFloorIndex/towerLevelIndex), Theater progress, friendship-10 count; showcase row (up to
  the player's shown characters, with level and constellation); build panel per character when
  `avatarInfoList` exists: weapon (level, refinement), 5 artifacts with main/substats and crit value
  (reuse the Artifact scorer), final stats from `fightPropMap` (2000 HP, 2001 ATK, 2002 DEF,
  20 CRIT Rate, 22 CRIT DMG, 23 Energy Recharge, 28 Elemental Mastery, 40-46 element DMG% —
  verify ids against Enka's docs), talents, constellations.
- States: loading skeleton, not found, details hidden ("turn on Show Character Details in your
  in-game profile"), maintenance, busy (show when to retry), share link (copy URL), refresh button
  that respects the ttl ("updates in N s").
- Look: like the CoC player tracker (`/coc/player/`) but in the Genshin design system; the hero is
  the player's namecard, drawn like the in-game profile card.
- Recent searches in localStorage (UIDs only).
